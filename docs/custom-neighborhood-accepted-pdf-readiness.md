# Accepted neighborhood PDF readiness

The Custom Property Report and Appraisal Report use the already-checked accepted neighborhood state for their neighborhood-only PDF readiness. An exact account/file-bound accepted group with ready geography and application group replaces the legacy assignment-details boundary check. It does not populate or confirm legacy fields. A raw section or assessment is not an accepted-state response; the existing loader still matches the complete saved section, receipt, revision, operation, attachment, report and account before producing that state.

Missing, loading, mismatched or unavailable state remains blocking. Explicitly verified legacy files retain the existing geometry/cardinal/confirmation checks. Signed PDF requests continue to use the server's immutable artifact. The server remains authoritative for originals, access, accepted-group coherence and all signing readiness.

Property Report finalization changes only this same obsolete neighborhood blocker. Assignment requirements, comparables, value, market study, unsaved changes, save barriers, server readiness, warning acknowledgment and signing identity checks remain unchanged.

The legacy Appraisal Report HTML preview does not render the accepted group. Its browser-print path therefore stays blocked for accepted groups and directs the user to download the checked server PDF. Signed files likewise direct the user to their immutable signed PDF, regardless of legacy-field completeness. This change neither redesigns that preview nor treats it as the accepted or signed report. The server PDF includes the accepted boundary and statistics; successful draft generation is not a claim that every finalization requirement is complete.
