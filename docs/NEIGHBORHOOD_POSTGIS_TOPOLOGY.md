# Source-preserving planar topology checkpoint

`createNeighborhoodPostgisTopology(pool).build(input)` consumes the trusted cached-linework preparation envelope and creates source-backed planar faces. It is an internal inactive service: no route, schema, provider, worker, report consumer or production configuration is changed. The pool must already have bounded connection acquisition configured.

## Geometry policy

The initial supported projected CRS is EPSG26914 (NAD83 / UTM14N, metres), verified against the database spatial reference definition. The conservative input support window is longitude[-98.5,-95.5], latitude[31,34.5]; it is not a jurisdiction boundary or survey accuracy guarantee. Output includes authoritative projected EWKB, display GeoJSON4326 and observed PostGIS/GEOS/PROJ versions.

This version supports only zero snap. It transforms source vertices, nodes real line intersections and overlapping segments, and polygonizes actual closed faces. It never adds an envelope edge, endpoint connector, rectangle, circle, hull, buffer or geometry-repair fallback. A gap remains a gap. Nested faces retain holes; slivers under1m² are not silently discarded. Unsupported, invalid or over-budget results contain no usable partial graph.

Every edge retains all matching original source primitive occurrences, including feature, part, segment index and source-local endpoint ordering coordinates. The `postgis-planar-v3` policy binds each original endpoint and exact native original-pair intersection to its original primitive occurrence. Consecutive points in each source-local witness chain must match the exact endpoint bytes of an existing `ST_Node` output edge. It never constructs replacement edges. Every original consecutive chain and every output edge must be accounted for, including duplicate/retraced occurrences; missing evidence fails closed.

The retained `start_fraction`/`end_fraction` fields have explicit `dominant_axis_signed_order_coordinate_v1` semantics: use X when the original primitive's absolute X displacement is at least its absolute Y displacement, otherwise Y; exact original endpoint bytes are 0 and 1. Distinct witness points with tied ordering, or non-endpoints at/outside those bounds, are rejected. These coordinates are not a nearest-point calculation, distance ratio, or promise that interpolation reproduces the edge. Original `ST_Intersection` construction is authoritative only for this declared computational witness—not mathematical collinearity, provider accuracy or legal roadway identity. Noded geometry is unchanged, and no tolerance, snapping or nearest-source attribution is used. Planar crossings do not establish bridge/ramp travel connectivity or permission to cross a geographic barrier.

This deliberately supersedes the unmerged v2 interpolation-reconstruction policy. Native PostGIS3.5.2/GEOS3.9.0 demonstrated a bowtie intersection one floating-point ULP away from its interpolation reconstruction, although six original-pair intersection operand/orientation variants reproduced the native split point exactly. A versioned witness policy is necessary; accepting a small distance or claiming exact interpolated containment would hide that distinction. The v3 kernel and its independent native all-original-pairs audit merged in PR #622 and remain inactive. Subsequent changes still require fresh exact-head native acceptance; the test-only replay artifact described below is a separate, not-yet-accepted slice.

Multiple source occurrences on the same edge must additionally have positive-length exact interior overlap between their original projected primitives (`ST_Relate(...,'1********')`). This rejects non-collinear sources whose reconstructed substring bytes happen to coincide at floating-point precision. It preserves truly duplicated/overlapping support; incompatible multi-source attribution is incomplete, not silently assigned to a preferred source. These checks do not establish source accuracy or legal roadway identity.

## Bounded work before expensive noding

The service admits at most512 original adjacent-coordinate primitive segments before connecting. A separate projected-box overlap query performs at most130,816 unordered primitive comparisons and retains at most4,097 candidate pairs (4,096 plus overflow sentinel). It runs before `ST_Node` or polygonization.

Native admission first counts every original projected primitive and requires valid, nonempty geometry with finite, strictly positive length. Repeated adjacent vertices and projection collapse are rejected, not filtered out of source accounting. For an invalid primitive, pair enumeration and the build never run; the failure reports `invalid_source_primitive`, the full original primitive count and `invalid_primitive_count`, with pair count/bounds unknown and admission false. Valid-result admission shape is unchanged. Every original primitive is retained in the later build as well; no positive-length filter can conceal dropped evidence.

For S primitives, C original coordinates and P completely enumerated overlapping-box pairs, the conservative split-piece/source-reference upper bound is S+4P and the coordinate bound is C+8P. Witness construction additionally caps source-point incidences at2S+4P and consecutive source chains atS+4P. All adjacent, same-part, retraced and duplicate occurrences participate. Admission requires these bounds to fit the configured graph ceilings; truncated pair counts never become a claimed upper bound. Unexpected pair-intersection shapes, ambiguous source ordering and overflow are explicit incomplete results. No geographic-degree boxes or prefix truncation substitute for projected evidence.

Defaults additionally cap1,024 cells,8,192 edges,16,384 source references,32MB successful output and128KB per result row. The successful-output cap includes the exact UTF-8 JSON framing, status/revision fields and all metadata, checked separately from bounded manifest hashing work. Statement/read/acquisition ceilings are5s/20s/3s, with bounded rollback and connection cleanup. Callers can only lower limits. These are containment settings, not measured production latency. Dense or long road captures can require a future reviewed tile/seam approach; this version returns incomplete instead of silently simplifying them.

Failure control messages have a separate16KB maximum so even a requested one-byte payload limit can report a reason. They omit geometry, source descriptors, aliases and potentially large limitations, retaining only bounded hashes, counts and diagnostics with `metadata_not_returned`. A topology revision hashes normalized evidence, performed policy, admission and engine versions; its digest is neither authorization nor an independent geometry certificate.

## Testing and remaining scope

Synthetic Cartesian metre fixtures are explicitly translated to[700000,3600000] in26914 before transforming to4326. Expected square/curved/nested areas come from independent arithmetic, not supplied polygon outputs. Cases cover source gaps, duplicate evidence, intersections, corner contacts, dangles, closed/retraced/bow-tie lines, slivers, dense-crossing admission, deterministic content and failure controls.

The native suite uses the unchanged guarded unique-child PostgreSQL/PostGIS CI helper; it does not access a shared/live database or drop schemas/databases. Native outcomes must be recorded from the exact CI commit. Mock geometry rows and fixture arithmetic alone do not prove native SQL or topology validity.

## Test-only native replay candidate

The existing native `closedRing` case can retain its complete input and result after all of that case's assertions, independent original-source witness audit and metric audit have passed. After the existing native work and successful `pool.end()`, the test emits at most one diagnostic beginning `HOMENODE_NATIVE_TOPOLOGY_REPLAY_V1 `. No extra producer call, SQL, geometry operation, database setting, lifecycle change or workflow collector is introduced. An uncaught failure or failed pool cleanup prevents emission. A failing child test can still allow its parent to continue, and other workflow stages run later: the artifact therefore always says `candidate` and `whole_ci_outcome: unverified_at_emission`, never that the overall native suite or CI job passed.

The marker plus complete single-line JSON transport is capped at 128,000 UTF-8 bytes, excluding test-runner/TAP or log framing outside the diagnostic message. It contains `payload_json`, the exact UTF-8 byte count of that decoded string, and its SHA256. Recovery must remove only external log framing, preserve the whole marker/transport, verify its limit/count/hash, and require exact encode/decode round-trip identity. Hash the decoded `payload_json` bytes, not an independently reformatted JSON object. Truncation, changed content, ambiguous JSON or overflow is rejected; the separate truncating failure-diagnostic helper is never used for replay. Strict bounded plain-JSON validation rejects custom objects, accessors, `toJSON`, sparse/extra-property arrays, hidden or symbol fields, cycles, non-finite numbers and negative zero rather than silently changing or omitting data. Shared in-memory object identity is not part of JSON; all JSON field values are retained.

The payload preserves every supplied input/result field, including exact EWKB and GeoJSON, source occurrence references, versions, diagnostics, policies and admission limits. Its transport digest supplements, but does not replace, the producer's topology manifest digest. Source capture time and artifact emission time are separate. The execution identity is read from `git rev-parse --verify HEAD` in the fixed repository directory, alongside raw SHA256/byte counts for the producer, graph preparation, contract, native test, metric fixture and accepted CI database helper. These six raw files must match their exact checkout blobs before and after native work. This deliberately refuses even CRLF-only differences from a committed LF blob; it is a raw-byte equality policy, not Git's normalized clean-worktree check. Missing, changed or unavailable identity fails with a fixed diagnostic code, not arbitrary process output.

Only allowlisted GitHub Actions run ID, attempt, job key, declared SHA/ref and Node version are added. The declared CI SHA/ref are not substituted for the observed checkout. Numeric job ID and PR source SHA remain explicitly unresolved in the test; branch/ref text never establishes a PR source identity. A coordinator must independently bind the exact producing run, job, actual checkout and PR source head, and confirm that the entire run and every required CI check succeeded, before retaining this as accepted native evidence. Passing the chosen fixture or native job alone is insufficient. A candidate from a failed overall CI run is never accepted. No environment dump, connection string, database name, arbitrary error or real property data is exported. A digest is integrity evidence, not authorization or source authenticity.

No successful native replay artifact is claimed by local fixture-only tests. The first downstream pure perimeter replay can verify native-manifest admission while still correctly returning `upstream_boundary_validation_incomplete`. Positive perimeter descriptions require a separately verified selected-cell union, ordered edge cycles, subject containment, anchor and scope/date binding; this synthetic metric audit is not a neighborhood-selection receipt.

This result is not directly compatible with the selection engine or a report. A reviewed adapter still needs explicit cell eligibility/similarity, subject containment and geographic barrier policy. Zero-incident diagnostic edges must not masquerade as cell boundaries. Chosen cells still require actual dissolve/validity/perimeter verification and distinct competitive memberships. Immutable publication, source-reader orchestration, population statistics, research and atomic Custom/UAD application remain separate unactivated work.
