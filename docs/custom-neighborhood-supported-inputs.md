# Custom neighborhood calculation inputs

This adapter connects exact retained Custom capture/review inputs to the existing
`buildCachedNeighborhoodInputs` and `summarizeNeighborhoodPopulations` functions.
It is not a new statistics engine, source permission, verified-provider profile,
published assessment or report Apply endpoint.

## Installed reconstruction profile

The initial profile's basis is `retained_reviewer_reconstruction`. Existing
authorized review commands can supply explicitly reviewed computational inputs
after their complete bindings and dependencies are checked. Neither a `known`
label nor a saved hash proves that a fact is true. Original reviewer identities
and evidence remain attached; a reviewer UUID does not establish appraiser
licensure or signing authority. `authority: not_established` remains explicit.

The owner must load the exact retained preparation graph, saved selection and
current review state under the existing assignment, source-use, material and
transaction checks. The adapter accepts no browser-supplied verified flags,
arbitrary rule sets, source queries or replacement evidence. A later owner must
adopt and publish the result before any report Apply is offered.

The closed input also supplies `derived_at`, an actual owner clock reading in
UTC millisecond form. Derived evidence is dated when it is assembled, not backdated
to the older source capture or invented from a review claim. Original source and
review temporal strings remain separately retained and checked.

The fixed local housing catalog is `custom-reviewed-housing-v1`, revision `1`.
The eligible housing code comes from the subject's current reviewed housing at
the exact effective date. Missing or unsupported subject housing cannot be
replaced with a default property type or a label copied from CAD.

## Field-specific support

Housing support applies only to housing. The adapter constructs whitelisted
rows; it must not spread a current CAD row and add a reviewed historical date,
thereby accidentally promoting its GLA, age, site size or assessed value too.
Those optional characteristics, tax-year values, historical GLA at sale and
parcel allocations remain unavailable in this initial profile.

A transaction requires its current completion, closing date, USD recorded total
consideration, economic membership, completed-home and equivalence decisions,
plus a compatible study-fitness review referring to those exact current facts.
The closing date and amount must reconcile to the retained evidence. All current
material-condition decisions must be accounted for; unknown or present conditions
prevent this initial profile from treating the transaction as eligible.

Under this installed profile, `compatible` is an explicit retained reviewer
assertion of completed fitness/condition review for the named study. Every current
condition head remains a constraint and must be referenced exactly and known
absent. Empty condition history alone is not evidence that adverse conditions do
not exist; the overall reconstruction relies on that explicit reviewer assertion,
not an inference from missing records.

Equivalent source rows are not extra sales. All retained candidates in the
canonical group must be accounted for and agree; selecting one convenient source
cannot hide a conflict or a later unknown correction. Economic membership must
include unselected co-parcels and exact CAD links. Ambiguous multiple interests
collapsing onto one CAD account do not become a single-property sale.

A supported multi-account transfer contributes its recorded total once. It does
not supply that full amount to every house or a price per square foot without
supported allocation and GLA-at-sale evidence. Existing statistics semantics,
unadjusted prices, distinct-property coverage and exact pooled calculations remain
unchanged.

## Completeness and integration

The output binds the context, selection, review generation and installed profile.
Derived source payloads get their own content identities; original retained
payloads and their hashes are never rewritten. Unknown review corrections replace
older known claims. Dependencies that became superseded make the dependent review
unavailable rather than silently using its old value.

Every selected account and retained candidate remains accounted for. Review limits
are not parcel-selection or sale-count targets. This is a sparse review layer,
not a requirement to manually approve every parcel. The existing current-mirror
exploration stays separate and useful; a future installed CAD/source interpretation
profile can supply broad-area base facts without manufacturing historical support.

A transaction can be excluded as outside the selected pockets only when its
complete reviewed membership establishes that it is disjoint from the selection.
Unknown or partial membership cannot prove exclusion. Its retained candidate
references and exclusion reason remain in the audit even when it contributes no
calculation row.

Missing required support produces an incomplete calculation input. If subject
housing is unresolved, the cached/statistics result is absent rather than computed
using an invented eligibility type. Optional unknown measures stay unknown and do
not become zero, a predominant price, an appreciation rate or a reliability score.

The remaining owner integration must publish the exact boundary, selected pockets,
populations, statistics and evidence as one coherent group, then use the existing
Custom acceptance save/reopen path. This module neither enables production nor
changes accepted report sections, PDFs, signatures or another report type.

## Actual Custom service caller

`createCustomCohortContextCapture().prepareReviewedInputs()` owns the database
loading and calculation. Its closed input accepts the authenticated identity,
exact account/file/context, expected workspace section revision and expected
review generation. It does not accept source rows, selected account arrays,
review-state objects, policy grants or caller timestamps.

The existing assignment policy is checked before a parent-workfile lock and a
bounded read of the saved `neighborhood_workspace` section. Absent, malformed,
stale and pending-capture checkpoints cannot become a default broad selection.
An explicitly empty saved selection remains empty. The owner loads the exact
original capture only after current source-policy authorization, checks subject
freshness, and reads the exact current review snapshot. It uses an actual database
clock reading, conservatively normalizes it to milliseconds, and retains the
original microsecond reading separately.

The pure computation runs outside the database connection. Before returning,
the owner reacquires the assignment/workfile fences and rechecks the exact saved
checkpoint, subject material, review generation/digest and source policy. A
concurrent edit, review correction, subject replacement or revoked source grant
therefore prevents the old result from being presented as current.

This method is internal and source-bearing. No HTTP route exposes it, and the
existing internal-retention policy is not permission to disclose its contents.
The subsequent publication/presentation owner must obtain the appropriate source
exposure authorization and bind the coherent report group before offering Apply.
